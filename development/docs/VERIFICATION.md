The reported generic connection error did not reproduce with normal host access; the user's exact network/filter cause remains unconfirmed. The public YATA export was fetched successfully during 0.4.0 implementation. Official Torn OpenAPI 6.13.6 and Chrome permission documentation were consulted on this date.

Packaging is verified using a fixed 11-asset allowlist, deterministic ZIP construction and independent unzip checksum/manifest inspection. Incomplete build staging is rejected before installed assets change. The canonical root directory remains unchanged. Temporary browser profiles are created outside the extension folder and removed.

Snapshots in `travel-preview.png` and `war-preview.png` are controlled fixtures. They prove the rendered layout, not a production account's correctness. To accept the live integration: Reload the existing extension, connect your own Torn key in Options, enable/save YATA consent, compare a real flight route/stock catalog and current chain/opponent with Torn, then test physical sound/OS notifications. Unknown stock or capacity is never filled with invented values. Sleeping Chrome may delay notifications.

GitHub Actions repeats checks and browser flows on Linux/Node 24. A release tag must match manifest/package versions; the single extension asset is always `TornDashboard.zip` (plus checksum file). GitHub releases do not automatically update an unpacked Chrome installation. Use the same local folder + Reload, or the same Chrome Web Store listing for store updates.
